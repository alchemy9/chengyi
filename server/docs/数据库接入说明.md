# 数据库接入说明

## 你需要提供什么

建议先提供一个空数据库，后端负责创建数据表。需要确认：数据库类型、地址、端口、数据库名、访问账号、密码、是否要求 SSL，以及运行后端的电脑能否连接。

如你已经设计了数据表，请先提供表结构（建表 SQL 或字段说明）；后端会先适配，不能把现有表直接当作本项目的表。连接配置只放在后端 `.env`，不放入前端代码。

## 已规划的数据表

| 表 | 存储内容 |
| --- | --- |
| heritage_items | 物品名称、分类、地区、介绍、发布与演示标记 |
| hotspots | 物品可点击部位、讲解、动作类型与目标 |
| knowledge_entries | 补充知识、出处、审核状态 |
| tours | 历史路线数据，轻量版不使用 |
| visitor_sessions | 访客凭证摘要、当前物品、当前部位、有效期与版本；旧路线字段只保留兼容 |
| messages | 每轮请求与回答，讲解模式和动作 |
| interaction_events | 历史交互统计，轻量版不再采集 |
| model_calls | 模型名称、耗时、用量及错误类别；不存 API Key |
| alembic_version | 数据库结构的迁移版本 |

完整字段以 `app/models.py` 和迁移文件为准。轻量版新增 current_hotspot_id 保存部位上下文，不删除旧表和旧数据。物品和路线编号由项目约定，不依赖数据库自增编号。所有时间保存 UTC；访客凭证只保存 SHA-256 摘要。

## 配置形式

本地开发：

```dotenv
DATABASE_URL=sqlite:///./data/heritage.db
```

MySQL：

```dotenv
DATABASE_URL=mysql+pymysql://USERNAME:PASSWORD@HOST:3306/DATABASE?charset=utf8mb4
```

PostgreSQL：

```dotenv
DATABASE_URL=postgresql+psycopg://USERNAME:PASSWORD@HOST:5432/DATABASE?sslmode=require
```

这些是占位格式，不能直接使用。账号或密码包含 `@`、`:`、`/`、`#` 等特殊字符时，需要对该部分进行 URL 编码。SSL 参数应按数据库服务要求填写；不要为了连通而关闭证书验证。可参考 [SQLAlchemy 连接配置](https://docs.sqlalchemy.org/en/20/core/engines.html)。

接入新数据库之前，应先检查地址、空库状态和权限，再运行：

```sh
.venv/bin/python -m alembic upgrade head
```

切换连接不会自动搬迁本地资料和对话。正式资料迁移需另外执行导入流程；开发演示数据只在 `SEED_DEMO_DATA=true` 时插入，正式环境应关闭。

## 当前验证范围

SQLite 已完成实际运行和业务测试。MySQL、PostgreSQL 的驱动已安装，迁移已做离线 SQL 生成检查；真实连接、权限、SSL 和在线迁移要在你提供数据库后验证。
