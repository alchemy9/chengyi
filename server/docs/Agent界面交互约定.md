# Agent 与前端界面联动约定

日期：2026-10-15。首版后台接口与 `/voice` 参考页面已实现，下文区分已经支持的命令与正式前端仍需绑定的效果。接口以《前端对接说明》及 `/docs` 为准。

## 产品目标

访客通过说话或点击完成参观：打开藏品、观察部位、听取对应讲解，以及暂停、继续、重播。界面动作应在指令确认后立即执行，声音随后流式播放，不等整篇讲解合成完成。

保留已经确认的“按住说话、松开发送”。界面实时联动不要求持续开启麦克风。Agora 自由通话作为可选语音入口，接通测试已通过，实际问答、延迟及界面联动仍需单独验收。

## 首版操作范围与现状

| 用户表达示例 | 预期界面效果 | 当前状态 |
| --- | --- | --- |
| “打开青花缠枝莲纹碗” | 切换到 C001，并更新讲解上下文 | 后台命令解析与测试页切换、回执已实现 |
| “看看碗心”“看看外壁” | 定位已登记部位，并触发部位讲解 | 后台目标匹配、测试页部位选中及回执已实现 |
| “暂停讲解”“继续播放”“再讲一遍” | 操作当前播放器 | 支持文字指令、录音转写指令和播放器状态回执 |
| 点击已配置的互动部位 | 高亮、播放指定动画或展示指定步骤 | 后台返回 highlight、play_animation、show_steps；实际视觉效果由前端实现 |

旋转、缩放、切换制作步骤等操作，需要先确认正式前端确实提供对应能力与状态，再扩展；现有后台不能控制任意网页，也没有通用的屏幕操作权限。

## 分工与执行顺序

1. 前端提供当前页面、物品编号、部位编号和实际播放状态；语音入口先取得用户授权并完成转写。
2. 后台识别意图，结合当前场景确定目标；只接受已发布物品、已登记部位与前端实际支持的操作。
3. 对确定的动作尽早下发指令，前端更新界面；需要讲解时，并行走 Dify 知识库问答与流式语音。
4. 前端返回执行成功、失败或不支持。只有收到成功反馈，讲解助手才可以说“已经打开”“已经切换”。

常用口令与明确的藏品、部位名称由轻量命令解析器直接处理，不额外等待一次模型回答。支持“请帮我打开…”“我想看看…”“把…打开”“看看这件藏品的…”等句式、编号、完整名称和唯一的名称片段。第一版不做任意语义推断，不把规则匹配描述为 Dify 模型工具调用；未识别的普通问题继续交给 Dify，含糊的操作则提示选择。

## 已实现的动作接口

保留现有 Reply.actions 协议，避免破坏已有前端。新增独立 HTTP 操作通道，先执行动作并确认结果，再发起现有文字或声音流；不需要等 Dify 生成正文，也没有增加 `ui_action` SSE 事件。

| 方法 | 会话下的路径 | 用途 |
| --- | --- | --- |
| GET | `/ui/state` | 当前会话、可用动作类型和未完成动作 |
| POST | `/ui/plan` | 解析自然语言，返回动作、普通问题或澄清选择 |
| POST | `/ui/actions/{action_id}/receipt` | 前端报告执行结果，成功后返回可选讲解请求 |
| POST | `/ui/context` | 同步手动选择的物品与部位，并取消旧动作 |
| POST | `/ui/cancel` | 取消未完成动作，使迟到的旧请求失效 |

以上路径均加 `/api/v1/sessions/{session_id}`，必须携带 X-Session-Token。动作类型限定为 open_item、focus_hotspot、audio_pause、audio_resume、audio_repeat、audio_stop；与旧 Reply.actions 的三个视觉动作类型分开。

`ui/plan` 接收 text、expected_revision、client_request_id（UUID）和 supported_actions。前端只声明自己已经实现的动作；不支持的操作不会下发。返回 decision 为 action、ask、clarify 或 completed，并提供会话状态；clarify 的 choices 可以做成按钮，再把对应 text 发回 plan。

动作携带 id、type、item_id、hotspot_id、expected_revision、expires_at，有效期 60 秒。签发动作只增加会话版本，不立即改变当前物品或部位。动作处于未完成状态时，讲解请求返回 409；前端需先执行、反馈或取消。

前端只执行白名单动作，按 action_id 去重，丢弃旧请求或旧场景下的迟到动作。物品切换与部位选择应先同步后台上下文，避免界面展示新物品、讲解却仍对应旧物品。

回执必须提交 expected_revision、status（applied、failed、unsupported、cancelled），成功时带 actual_item_id、actual_hotspot_id；播放器操作还需 playback_state（playing、paused、stopped）。后台验证目标、有效期和版本后才更新上下文。回执返回 interaction 时，再发送到现有 `/interact/voice-stream?audio_format=pcm`。

同一 client_request_id 的相同计划重试不会新建动作，改动请求内容会返回 409。相同回执可重试，duplicate=true 时不再返回 interaction，不能重复发起讲解。迟到、取消、过期或目标不一致的回执会被拒绝。收到失联或冲突时，重新读取状态并对齐界面，不自动猜测已完成。

不会执行模型生成的 JavaScript、任意 URL 或未登记的页面动作。对象名称存在多个匹配、用户表达不清、指令含否定或要求一次执行多个步骤时，先确认或降为普通问答，不能根据猜测跳转。

## 前端联调需要提供

- 页面及藏品清单，与后台 item_id 一一对应；知识库里有介绍不等于前端已有可打开的展品。
- 每件藏品的可点击部位及 hotspot_id，与已有动作 target 的对应关系。
- 实际支持的操作：页面切换、高亮、动画、步骤展示和播放控制。
- 执行完成与失败的反馈方式，以及取消讲解、切换物品时的清理行为。

前端的技术框架不影响以上业务约定。参考客户端为 `app/static/ui-controls.js`，测试页在 `/voice`。正式前端替换其中的页面更新和播放器处理器即可；3D 镜头、模型旋转、真实动画和步骤展示仍需正式前端提供。

## 验收场景

- 说出准确藏品名后，界面与后台当前物品一致；后续“这个”指向新物品。
- 说“看看碗心”后，界面定位碗心，回答使用相应部位与知识库资料。
- 问“这个碗的用途是什么”只回答问题，不误触发页面跳转。
- 不存在、未发布或有重名的目标，不随意切换；不支持的动作明确反馈。
- 同一动作重复到达只执行一次；切换物品后旧动作和旧声音不再生效。
- 动作与语音并行；识别、界面执行、首段文字和起播耗时分别记录，不能用频道连接成功代替交互验收。
