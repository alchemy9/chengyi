# 轻量版前端对接说明

2026-10-15：Dify Agent、文字流、分句语音输出和 WAV 录音转写已实现。完整字段见 `openapi.json` 或开发环境 `/docs`。

## 基础约定

开发地址 `http://127.0.0.1:8000`，下表路径统一加 `/api/v1`。普通成功响应为 `{"data":{},"request_id":"请求编号"}`；失败为 `{"error":{"code":"错误类别","message":"提示","request_id":"请求编号"}}`。响应头含 X-Request-ID。

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/items` | 已发布物品，支持 search、category、page、page_size（最多 100） |
| GET | `/items/{item_id}` | 物品及可点击部位 |
| POST | `/sessions` | 创建访客会话与凭证 |
| GET | `/sessions/{session_id}` | 当前物品、部位与会话状态 |
| POST | `/sessions/{session_id}/interact` | 完整文字回答 |
| POST | `/sessions/{session_id}/interact/stream` | SSE 文字回答 |
| GET | `/voice/status` | 声音与识别接入状态，不返回密钥 |
| POST | `/sessions/{session_id}/interact/voice-stream` | SSE 文字与分句声音 |
| POST | `/sessions/{session_id}/transcribe` | 短 WAV 录音转写及明确播放指令识别 |
| GET | `/sessions/{session_id}/ui/state` | 界面状态、待执行动作与动作类型 |
| POST | `/sessions/{session_id}/ui/plan` | 自然语言操作解析 |
| POST | `/sessions/{session_id}/ui/actions/{action_id}/receipt` | 界面执行结果回执 |
| POST | `/sessions/{session_id}/ui/context` | 手动界面选择同步 |
| POST | `/sessions/{session_id}/ui/cancel` | 取消旧动作及迟到请求 |

## 会话与上下文

创建会话发送 JSON：`{"item_id":"C001","audience":"general"}`。item_id 可省略，之后选择物品；audience 为 general、children、expert。

保存创建响应的 `data.session.id` 和 `data.session_token`，后续会话请求必须带 `X-Session-Token`。默认有效期 24 小时，凭证无效返回 404，过期返回 410。

后台维护当前物品、部位及最近十条本物品的有效对话。每次 Dify 请求新建远程会话，将这些上下文明确传入；前端不需要管理 Dify conversation_id，也不能自行提交供应商 user 标识。网页 Dify 测试历史与 API 历史互相隔离。

同一访客会话串行请求，并发冲突返回 409。连接意外中断时先读取会话 revision、turn_count，确认是否已保存；不要自动重复提交付费请求。

## 讲解请求

| event | 字段 | 行为 |
| --- | --- | --- |
| explain | 可选 item_id | 介绍指定或当前物品，清除局部选择 |
| hotspot | 必填 hotspot_id，可选 item_id | 讲解部位并记住它 |
| ask | 必填 question，可选 item_id | 根据当前物品、部位连续回答 |

```json
{"event":"hotspot","item_id":"C001","hotspot_id":"bowl-center"}
```

```json
{"event":"ask","question":"这个纹样有什么寓意？"}
```

切换物品自动清除旧部位，只带入新物品相关历史。讲解结果包含 text、mode、actions、session、sources、usage、suggestions、warning、provider_error、request_id、message_id。

mode 为 demo、live 或 fallback。fallback 是模型失败后的本地资料讲解，必须在前端提示；连接测试不回退为假成功。

sources 包含后台提供的本地资料，以及 Dify 本次实际检索返回的文档来源。Dify 来源 id 以 `dify:` 开头，title 是文档名，source_name 是知识库名称，不返回整篇正文。这些来源不等于逐句事实核验。usage 为空表示供应商没有提供，不能理解成零费用。

actions 由后台资料配置，只有 highlight、play_animation、show_steps 三类，由正式前端绑定实际效果；不能执行模型输出的任意动作或代码。普通追问不会重复执行上次点击动作。

## 文字流

POST 使用 fetch 读取 SSE，不能直接用原生 EventSource。每个事件以空行分隔：

```text
event: delta
data: {"text":"这件作品……"}

```

start 表示请求开始；delta 追加文字；reset 清除临时文字；result 为完整已保存回答，应在这里更新状态并执行动作；error 为失败。

开始前校验错误使用普通 HTTP 错误，流开始后错误可能仍为 HTTP 200，必须检查 error 事件。连接结束却没有 result，不能当作成功。

## 声音流

voice-stream 使用相同的交互 JSON 和会话凭证，保留全部文字事件，并新增：

| 事件 | 内容与处理 |
| --- | --- |
| speech_pending | 某句正在合成，包含 epoch、sequence |
| audio | audio_base64、mime_type、text、epoch、sequence、elapsed_ms 与供应商耗时 |
| speech_error | 声音失败；已有文字结果仍可显示 |
| speech_warning | 例如声音长度限制；完整文字仍可显示 |
| voice_done | 本轮合成结束与耗时统计，不等于前端实际播放结束 |

audio 为一小句完整 MP3，解码 Base64 后创建 Blob URL，按 sequence 顺序排队播放。每句合成时显式请求供应商流式返回，为浏览器兼容性，后端收齐这一小句后返回；不是逐音频字节推给浏览器，也不等待整篇回答。

reset 时停止旧声音、清空播放队列与文字、更新 epoch，并丢弃旧 epoch 的音频。新提问或切换物品也要停止旧声音。播放结束或离开页面时释放 Blob URL。

voice_done 指标包含 first_text_ms、text_done_ms、first_audio_byte_ms、first_audio_ready_ms、total_ms、segments、resets、speech_error。实际播放时间由浏览器测量，不能把后端第一字节耗时当作用户已经听到声音。

## 低延迟音频流（新增）

声音体验页现在请求 `/interact/voice-stream?audio_format=pcm`。默认不传此参数时仍返回原有分句 MP3，兼容已有前端。

PCM 模式增加 audio_start、audio_chunk、audio_end 事件，仍保留文字、错误和 voice_done。audio_chunk 的 audio_base64 是单声道、24kHz、16 位小端有符号 PCM，encoding 为 pcm_s16le，包含 epoch、sequence 和 elapsed_ms；网络包不代表整句结束。校验 epoch 后立即解码进入 Web Audio 队列，不要等到 audio_end 或 voice_done 才播放，也不能将 PCM 当 MP3 或直接给 audio 元素。

参考 `app/static/pcm-player.js`，它保留短播放缓冲，支持暂停、继续、停止和重播。第一次点击提问或录音时即激活 AudioContext；若浏览器限制自动播放，提示用户点击继续。切换物品、新提问和 reset 必须清空旧缓冲，离开页面关闭音频上下文。

后端第一小段最多约 28 字，并优先在自然停顿处发起合成；后续保持较长句段。PCM 字节到达即转发，不收齐整句；同一轮合成复用 HTTP 连接。first_speech_request_ms 表示实际开始首段合成；PCM 模式 first_audio_ready_ms 表示首批可播放采样到达，MP3 模式仍表示首句文件准备好。前端起播时间按 AudioContext 计划起播点记录，不能等同于物理扬声器实测。

## 按住录音与语音控制

录音格式固定为单声道、16kHz、16 位 PCM WAV，0.2–30 秒、最多 1MiB。录音开始前暂停播报；WAV 是真实编码格式，不能把 WebM 改名后上传。

转写接口发送原始文件字节，Content-Type 为 `audio/wav`，不是 JSON，也不是前端 multipart。后端会转成 Dify 需要的 multipart 并调用工作区默认识别模型。

```js
const response = await fetch(base + '/api/v1/sessions/' + sessionId + '/transcribe', {
  method: 'POST',
  headers: {'Content-Type': 'audio/wav', 'X-Session-Token': sessionToken},
  body: wavBlob
});
```

返回 data.text、data.command、data.latency_ms。旧前端可继续使用 command 和 ask；新版测试页将所有转写 text 交给下方 ui/plan，统一处理页面动作、播放控制和普通提问。转写接口不会调用聊天 Agent，也不会修改会话轮数。

新版支持明确口令打开藏品、定位部位与执行反馈。实际录音参考 `app/static/voice.html` 与 `recording-worklet.js`。Web Audio 与录音需要安全来源，localhost 可用于本机测试，远程前端应使用 HTTPS。

## 自然语言与界面联动

先 GET `/sessions/{id}/ui/state` 取得最新 session.revision，再发送：

```json
{
  "text": "请帮我打开青花缠枝莲纹碗",
  "expected_revision": 1,
  "client_request_id": "6684a844-a14c-4783-9f7e-d162ab4dbe4e",
  "supported_actions": ["open_item", "focus_hotspot", "audio_pause", "audio_resume", "audio_repeat", "audio_stop"]
}
```

POST 地址为 `/sessions/{id}/ui/plan`。decision=action 时先执行 action；ask 时直接使用 interaction 调讲解接口；clarify 时显示 message 和 choices，用户选择后将 choice.text 重新发给 plan；completed 表示请求已经处理或失效，不执行旧动作。

action.id 用于去重；expected_revision 和 expires_at 用于拒绝旧动作。签发动作后 session.revision 会变化，应使用响应中的版本。执行后 POST `/sessions/{id}/ui/actions/{action.id}/receipt`：

```json
{
  "expected_revision": 2,
  "status": "applied",
  "actual_item_id": "C001",
  "actual_hotspot_id": null
}
```

status 支持 applied、failed、unsupported、cancelled。播放动作成功时，还需 playback_state=playing、paused 或 stopped。实际目标必须与 action 一致；失败时后台不会修改当前物品或启动讲解。回执成功后将返回 session 与可选 interaction，只有 interaction 非空且 duplicate=false 时才发起语音或文字讲解。

同一计划重试保留相同 client_request_id 与原请求内容，相同回执可安全重试；不要自动重新生成请求编号重发动作。后台提供 resolver=local_commands，表示首版使用本地明确句式与目录匹配，普通问题仍由 Dify 回答；不保证任意说法都能自动操作。

手动切换藏品或部位时 POST `/sessions/{id}/ui/context`，提交 expected_revision、item_id、可选 hotspot_id；停止时先取消前端网络与音频，再 POST `/sessions/{id}/ui/cancel`，提交 expected_revision。它们会更新版本并取消旧动作。遇到 409 先重新读取状态，不执行迟到结果；60 秒过期动作的回执返回 410。详细交互范围和示例处理器见《Agent界面交互约定》及 `app/static/ui-controls.js`。

## 管理与跨域

POST `/admin/login` 提交 username、password，拿到 8 小时 bearer token。管理页面只在内存保存 token。

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET / PUT | `/admin/model` | 接入配置，写入 provider、api_base_url、model、可选 api_key |
| POST | `/admin/model/test` | 短真实模型调用，直接报告成功或失败 |
| GET / PUT | `/admin/speech` | enabled、voice、可选 api_key（硅基流动） |
| POST | `/admin/speech/test` | 生成一段测试 MP3 |
| GET / POST | `/admin/items` | 查询 / 新增物品 |
| PUT | `/admin/items/{item_id}` | 完整更新物品 |

模型 provider 为 dify 或 chat_completions。Dify 地址为 `https://api.dify.ai/v1`，model 只是后台显示名称；实际大模型与知识库在 Dify 配置。相同平台可留空 api_key 保留旧 Key，切换平台需新 Key。

开发页面保存配置立即生效；正式环境通过服务器环境变量配置。发布物品用 published=true，补充知识 reviewed=true 才进入本地上下文。

CORS_ORIGINS 精确填写正式前端来源，修改后重启。当前本机 127.0.0.1 地址不能直接供另一台电脑访问，需要共同可达的联调服务器。
