# 首版语音交互

已确认采用“按住说话、松开发送”，后台保留资料、大模型、前端接口三个业务板块。

## 已实现

- Dify 旧版 Agent 接入，保留物品、部位和本地最近对话上下文。
- Dify 工作区默认模型识别短 WAV 录音，前端不持有密钥。
- 普通转写问题作为 ask 事件交给 Agent，并经硅基流动分句合成 MP3。
- 文本与声音并行处理，前端按顺序播放，显示等待时间。
- 明确的暂停、继续、重播、停止短语返回播放指令，前端操作已有播放器。
- 思考事件和已知思考标签不进入访客正文或朗读文本；错误不回传供应商秘密。

体验页面 `/voice` 包含按住录音、文字输入、物品与部位选择、播放控制和测速；管理页面可以更换六种播报音色。

## 流程

前端取得用户麦克风授权后，按住时开始录音并暂停播报，松开后结束录音。录音编码为单声道、16kHz、16 位 PCM WAV，时长 0.2–30 秒，最大 1MiB。

先发送 `/sessions/{id}/transcribe`，得到文字和可选播放指令。控制指令由前端执行，不调用聊天模型；普通问题随后发到 `/interact/voice-stream`。

同一会话串行处理。新的提问清理旧声音队列。播放暂停保留位置，重播使用已经生成的声音，停止可取消本轮请求。录音不会自动取消整轮正在生成的问答；需要先用停止按钮结束当前请求。

Dify 应用 Key 只保存在后端，识别与聊天使用同一稳定访客标识。实际播放由前端完成，Agent 不能直接开启麦克风、执行页面动作或确认没有反馈的操作。

## 当前边界与验收

已通过真实录音文件转写、Dify 问答、硅基流动合成和浏览器音频播放；69 项 Python 检查与 4 项客户端控制器检查通过，包括声音、识别、界面动作和回执。真实用户的麦克风采集、权限、按住和松开操作以及手机兼容性仍需人工验收。

识别存在错字风险，测试欢迎语中的“非遗”曾转写为同音错字，准确率尚未验收；含糊对象由 Agent 确认，不能猜测用户指的是哪件藏品。

明确口令现在可以打开已发布藏品、定位已登记部位，并等待前端执行回执。测试页已提供文字和录音转写两种入口；正式前端需绑定其实际页面与模型。路线导航和持续收音暂缓，Agora 自由通话单独验收。

2026-10-15 补充：界面操作走 ui/plan 与 receipt，不等待讲解生成。常见句式与目录匹配由本地轻量解析器处理，普通问题仍交给 Dify；不能确定目标时让用户选择。详见《Agent界面交互约定》。保留按住说话入口，不把 Agora 频道连接成功当作完整交互已完成。

正式前端应验证权限拒绝、录音为空、识别失败、模型失败、声音失败、暂停继续、重播、切换物品时清理旧音频，以及断线后不重复提交。
